# 逆ジオコーディング（座標 → 住所）

> 対象読者: 緯度経度を扱うアプリを作る人。
> ねらい: 「座標から地名を出す」処理を**どこに任せるべきか**を理解する。
> 本アプリでどちらを採用したかの判断は [pre-research/geocoding/](../pre-research/geocoding/)。

## 1. 用語

| 用語 | 意味 |
|---|---|
| **ジオコーディング** | 住所 → 座標（「東京駅」→ 35.6812, 139.7671） |
| **逆ジオコーディング** | **座標 → 住所**（35.6812, 139.7671 →「東京都千代田区」） |

GPSから得られるのは座標だけなので、**人間に伝えるには逆ジオコーディングが要る。**

## 2. ⚠️ LLMに座標を渡して住所を答えさせてはいけない

**これが最大の学び。** 生成AIを使うアプリでは「LLMに座標を渡せば地名を教えてくれる」と
期待しがちだが、**実測で約40km離れた市を答えた**。

なぜ苦手なのか:

- LLMは**座標と地名の対応表を厳密に持っているわけではない**。
  学習データから「もっともらしい地名」を生成しているにすぎない。
- しかも**間違い方が厄介**で、「隣県の実在する市」のような**それらしい答え**を返す。
  明らかに変な答えなら気づけるが、これは気づきにくい。
- 位置が回答の土台になるアプリでは、**ここがずれると後続の回答すべてがずれる**
  （例: 誤った市名でWeb検索してしまう）。

> 📌 **教訓**: **確定した事実は、LLMに推測させず、専用のAPIで解決してから渡す。**
> そしてプロンプトで「この住所は正確です。自分で座標から推測しないこと」と明示する。
> これは住所に限らず、**日付・為替・在庫数など「調べれば確定するもの」全般に当てはまる**。

## 3. 選択肢（日本で使う場合）

### Amazon Location Service（AWSを使うなら本命）

```python
import boto3
c = boto3.client("geo-places", region_name="ap-northeast-1")
r = c.reverse_geocode(QueryPosition=[lon, lat], MaxResults=1)  # ⚠️ 経度が先
addr = r["ResultItems"][0]["Address"]
addr["Region"]["Name"]  # 東京都
addr["Locality"]        # 千代田区
```

- ✅ **県名・市名が構造化されて返る**（そのままプロンプトに埋められる）
- ✅ AWS内で完結（外部APIキー不要、IAMで権限管理）
- ✅ **インデックスの事前作成が不要**（旧 `location` APIの `PlaceIndex` は要作成だった）
- 実測 **110〜160ms**、東京リージョンで利用可

### 国土地理院（GSI）— 日本専用・無料

```
GET https://mreversegeocoder.gsi.go.jp/reverse-geocoder/LonLatToAddress?lat=35.6812&lon=139.7671
-> {"results":{"muniCd":"13101","lv01Nm":"丸の内一丁目"}}
```

- ✅ **無料・APIキー不要**、精度も十分、速い（60〜230ms）
- ⚠️ **市区町村コード**（`13101`）が返る。県名・市名の文字列が欲しければ
  **約1900件の対応表を自前で持つ必要がある**
- ⚠️ 日本国内のみ。AWS外への通信になる

### その他

Google Maps Geocoding API、OpenStreetMap（Nominatim）など。
いずれも**APIキー管理**や**利用規約（商用可否・レート制限）**の確認が要る。

## 4. 実装で必ず踏む罠

| 罠 | どうなるか |
|---|---|
| ⚠️ **経度と緯度の順番** | Amazon Location は `[経度, 緯度]`。**逆に渡すと違う場所が返る**（エラーにならないので気づきにくい）。テストで固定しておく |
| **海上・国外はヒットしない** | 結果が空で返る。**例外にせず「住所なし」として処理を続ける**設計にする |
| **返る住所が詳細すぎる** | `Label` は建物名や番地まで含む（実測では店舗名やトイレの名前まで）。**読み上げや保存には県+市だけを使う** |
| **APIの障害で機能全体が止まる** | 住所解決は補助情報。**失敗したら住所なしで続行**する（本来の処理を殺さない） |

## 5. ⚠️ 位置情報はプライバシー情報

- **座標も住所も個人情報**として扱う。「どこにいたか」は本人の行動記録。
- ⚠️ **ログに出やすい。** デバッグでプロンプトやリクエストをログ出力すると、
  そこに座標や住所が残る（CloudWatch等に長期保存される）。
- 公開リポジトリに**実際の座標を書かない**。検証結果を残すときは
  **東京駅などの公共ランドマークで再現**する。

## 6. 方角の計算は自分でできる

逆ジオコーディングとは別に、「2点間の方位」は**APIを使わず計算できる**。

```python
import math

def bearing(lat1, lon1, lat2, lon2):
    """点1から点2への方位（真北を0度とする時計回りの角度）"""
    p1, p2 = math.radians(lat1), math.radians(lat2)
    d = math.radians(lon2 - lon1)
    y = math.sin(d) * math.cos(p2)
    x = math.cos(p1) * math.sin(p2) - math.sin(p1) * math.cos(p2) * math.cos(d)
    return (math.degrees(math.atan2(y, x)) + 360) % 360
```

- 「進行方向」は**GPSを2点取って**この式にかければ出る。
- **これもLLMに計算させない**（§2と同じ理由）。計算で確定するものは計算する。
