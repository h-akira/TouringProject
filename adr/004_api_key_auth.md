# 004. APIの保護をIP制限からAPIキーに替える

- **日付**: 2026-08-15
- **ステータス**: 採用
- **現在の設計**: [docs/01_architecture.md](../docs/01_architecture.md) §8・§9

## 背景

**APIには認証が無く、リソースポリシーによるIP制限だけで凌いでいた。**
URLが漏れれば誰でも叩けて、**1リクエストごとにBedrockの課金が発生する**状態を
「自分のIPからしか来られない」ことで塞いでいた。

これが**実用に耐えないと判明した**。理由は2つあり、どちらも運用でなく前提の問題:

- ⚠️ **IPは何もしなくても変わる。** 一般的な回線のグローバルIPは動的で、
  実際に変わって締め出された。**変わるたびに再デプロイが要る。**
- ⚠️ **走行中は必ずモバイル回線になる。**
  スマホが4G/5Gだと自宅Wi-Fi経由のMacとは別IPになるため、
  実機テストのたびに**同じWi-Fiに繋ぐ必要があった**。
  そして**本番の使い方（走りながら）は原理的にIPが変わり続ける。**

つまりIP制限は「開発中の一時しのぎ」ですらなく、**本来の使い方を試せなくしていた。**
音声化（US-2.01/02）に進む前に外す必要があった。

## 選択肢

### 案A: API Gateway のAPIキー（採用）

キーをスタックが生成し、アプリの設定画面から入力して `expo-secure-store` に保管する。
Usage Plan でキー単位の流量制限をかける。

### 案B: Cognito（JWT）

**却下。** 利用者が1人で、**ログインという概念が要らない**。
ユーザープール・トークン更新・サインイン画面を抱える割に、得られるのは同じ
「他人に叩かせない」だけ。⚠️ **複数ユーザーに広げるなら再検討する。**

### 案C: Lambda オーソライザーで独自トークンを検証

**却下。** APIキーとUsage Planで足りることを自前で書くことになる。
**検証のためだけにLambdaが1回余分に起動する**ので、レイテンシもコストも増える。

### 案D: IP制限のまま、動的DNS等でIPを追随させる

**却下。** 走行中のモバイル回線という**本質的な問題が解けない**。
自宅からの開発は楽になるが、実機での本番相当のテストは相変わらずできない。

## 決定

**案A（APIキー + Usage Plan）を採る。** IP制限は**残さず削除**した。

⚠️ **併用しない。** 残せば「キーが正しいのにIPで弾かれる」という
切り分けの難しい403を作るだけで、キーがある以上IPで絞る意味が無い。

### キーは全エンドポイントで必須、`/health` だけ例外

**オプトアウト方式にした**（既定で必須、個別に外す）。
逆にすると**新しいエンドポイントに付け忘れたときが穴になる**ため。

`/health` を外したのは、**「APIが落ちているのか、キーが違うのか」の切り分けに使う**から。
キーが要る死活監視は、その用途を果たせない。課金対象を呼ばず固定値を返すだけなので
開けておく実害も無い。

### ⚠️ キーの値はスタックのOutputsに出さない

出しているのは**キーのID**だけ。Outputs は `describe-stacks` の権限があれば読めるうえ、
**CIのログにも残る**。値はデプロイ後に `aws apigateway get-api-key --include-value` で取る
（手順は [Backend/README.md](../Backend/README.md)）。

### ⚠️ キーは `.env` に置かない

`EXPO_PUBLIC_*` は**バンドルに平文で埋め込まれる**ので、秘密の置き場にならない。
アプリの設定画面から入力し、`expo-secure-store`（AndroidではKeystoreで暗号化）に保管する。
**URLは秘密ではない**ので `.env` のままでよい。

## 影響

- ⚠️ **クォータは「問い数」ではなく「呼び出し回数」で効く。**
  1問 ＝ `POST` 1回 ＋ ポーリングの `GET` 約10回なので、**約11倍ずれる**。
  「1日200問」のつもりで200を設定すると**約18問で打ち止め**になる。
- ⚠️ **`ThrottleRate` を1にできない。** アプリのポーリングは1秒間隔なので、
  毎秒1回だと**自分の質問が429で弾かれる**。
- ⚠️ **ポーリング中の429は諦めない。** 一時的にレート上限へ触れることがあるため、
  アプリは打ち切り時間まで再試行する（403は即座に諦める）。
- **モバイル回線から叩けるようになった。** 実機テストで同じWi-Fiに繋ぐ制約が消えた。
- **403の原因が変わった。** 「IPが違う」ではなく「キーが違う／デプロイ漏れ」の2つになる。
- **設定画面が増えた**（`App/src/app/settings.tsx`）。走行中には使わない。
- ⚠️ **予算による自動遮断は未実装のまま。** クォータで日次の頭打ちはできたが、
  上限に張り付き続ければ課金は積み上がる。AWS Budgets は別途要る。
