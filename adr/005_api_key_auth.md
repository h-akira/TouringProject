# 005. API の保護を API キー ＋ Usage Plan にする

- **日付**: 2026-08-15（最終更新 2026-09-27）
- **ステータス**: 採用

## 背景

API は URL が漏れれば誰でも叩け、1リクエストごとに Bedrock の課金が発生する。
走行中のスマホは必ずモバイル回線につながり、グローバル IP は変わり続ける。

## 選択肢

| 案 | 判断 |
|---|---|
| **A. API Gateway の API キー ＋ Usage Plan** | 採用。キーはスタックが作り、アプリの設定画面から入力して `expo-secure-store` に保管する。キー単位で流量を制限できる |
| B. リソースポリシーで IP を制限する | 却下。IP は何もしなくても変わり、変わるたびに再デプロイが要る。走行中はモバイル回線なので原理的に使えない。キーと併用すると「キーは正しいのに IP で弾かれる」切り分けにくい 403 を作るので、併用もしない |
| C. Cognito（JWT） | 却下。利用者ごとのアカウントは作らない（[docs/00_user_stories.md](../docs/00_user_stories.md) §5）。ユーザープール・トークン更新・サインイン画面を抱える割に、得られるのは同じ「他人に叩かせない」だけ。複数ユーザーに広げるなら再検討する |
| D. Lambda オーソライザーで独自トークン | 却下。API キーと Usage Plan で足りることを自前で書くことになり、検証のために Lambda が1回余分に起動する |

## 決定

案A を採る。

- キーは全エンドポイントで必須（既定で必須にし、個別に外す）。新しいエンドポイントに付け忘れても穴にならない。
- `/health` だけ例外。「API が落ちているのか、キーが違うのか」の切り分けに使う。課金対象を呼ばず固定値を返すだけ。
- ⚠️ キーの値はスタックの Outputs に出さない（出すのはキーの ID だけ）。Outputs は `describe-stacks` の権限で読め、CI のログにも残る。
- ⚠️ キーはアプリの `.env` に置かない。`EXPO_PUBLIC_*` はバンドルに平文で埋め込まれる。URL は秘密ではないので `.env` でよい。

## 影響

- ⚠️ クォータは「問い数」ではなく「呼び出し回数」で効く。1問は `POST` 1回＋ポーリングの `GET` 約10回なので、「1日200問」のつもりで200を設定すると約18問で止まる。
- ⚠️ `ThrottleRate` を1にできない。ポーリングは最初の30秒間1秒間隔なので、自分の質問が 429 で弾かれる。
- アプリはポーリング中の 429 では諦めず、打ち切りまで続ける。403 は即座に諦める。
- 403 の原因は「キーが違う」か「デプロイ漏れ」（API Gateway は未定義のパスに 403 を返す）の2つ。
- アプリに設定画面が要る（走行中には使わない）。
