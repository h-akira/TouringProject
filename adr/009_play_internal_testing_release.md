# 009. Playストア内部テストで配るための署名・ビルド構成

- **日付**: 2026-09-10
- **ステータス**: 採用

## 背景

**指定した相手にだけアプリを配りたい**（20人以下）。配信手段は
**Google Play の内部テスト**に決めた（一般には見えず、100人まで、審査待ちが無い）。
一般的な配信手段の比較は [learning/13](../learning/13_private_app_distribution.md)。

⚠️ **しかし配信手段を決めただけでは配れない。** 現状のビルドには
**Playが受け付けない点が3つ**ある。

| 現状 | なぜ困るか |
|---|---|
| `release` を **debug鍵で署名**している | ⚠️ **Playはdebug鍵を受け付けない** |
| **`versionCode` が `1` 固定** | ⚠️ **Playは同じ番号を二度受け付けない** |
| **`arm64-v8a` だけをビルド**している | ⚠️ **配る相手の端末を選べない**（32bit端末で動かない） |

⚠️ **`App/android/` は prebuild の生成物**なので、いずれの設定も
**config plugin から書く必要がある**（手で編集しても再生成で消える）。

## 選択肢

### A. `versionCode` の管理

| | 案 | 評価 |
|---|---|---|
| **A-1** | **`app.json` の `version` から自動導出** ✅ | **上げ忘れの経路が1本に減る。** 既に「`version` を上げたらタグを打つ」規約があり、そこに乗る |
| A-2 | `app.json` に `versionCode` を手で書く | ⚠️ **`version` と二重管理**になり、片方の上げ忘れが起きる |
| A-3 | CIのビルド番号を使う | ⚠️ **手元ビルドで番号が決まらない。** D-1（手動運用）と両立しない |

**A-1 を採用**。`1.34.0` → `13400`（`major*10000 + minor*100 + patch`）。
⚠️ **各桁が99を超えられない**制約がつくが、この規模では問題にならない。

### B. ABI（CPUアーキテクチャ）

**ローカルのビルド生成物を 18.9GB → 3.6GB に減らすため、`arm64-v8a` のみに絞っている**
（[withSingleAbi.js](https://github.com/h-akira/TouringProject_App/blob/main/plugins/withSingleAbi.js)・[docs/01c](../docs/01c_app_client.md) §8a）。

| | 案 | 評価 |
|---|---|---|
| **B-1** | **配信ビルドだけ全ABI**（環境変数で切替） ✅ | 日常の開発は軽いまま、配るものだけ全端末に対応する |
| B-2 | 常に全ABIに戻す | ⚠️ **ローカルが再び 18.9GB に膨らむ。** 絞った理由がそのまま復活する |
| B-3 | `arm64-v8a` のまま配る | ❌ **32bit端末・x86_64端末で動かない。** ⚠️ **配ってから気づく** |

**B-1 を採用**。⚠️ **切り替え忘れると arm64 だけのAABが上がる**ので、
**切り替えはAABを作る npm script に埋め込む**（人が環境変数を思い出さなくてよいようにする）。

📌 **AAB自体はABIごとの分割をPlay側がやる**ので、全ABIを入れても
**利用者がダウンロードするサイズは増えない。**

### C. 署名鍵（upload key）の保管

⚠️ **ここで前提を1つ訂正する。** 鍵は2種類あり、危険度が違う。

| | **app signing key** | **upload key** |
|---|---|---|
| **持ち主** | ✅ **Googleが保管**（Play App Signing） | **自分** |
| **役目** | ⚠️ **利用者の端末が「同じアプリか」を検証する本物の鍵** | Googleに投稿者が本人だと示すだけ |
| **失ったら** | ❌ **回復不能**（アプリを作り直すしかない） | ✅ **Play Consoleから再登録できる**（24〜48時間） |

📌 **Play App Signing に預ける限り、自分が持つのは upload key だけ**であり、
⚠️ **「鍵を失うと二度と更新できない」は当てはまらない。**
（`Play Store protection > Manage Play app signing > Request upload key reset`）

| | 案 | 評価 |
|---|---|---|
| **C-1** | **原本を `~/.keystore/`（リポジトリ外）に置くだけ** ✅ | ⚠️ **Play App Signing で復旧できるので、これで足りる** |
| C-2 | 秘密管理サービス（AWS Secrets Manager 等）に預ける | ⚠️ **アプリ側をAWSに依存させる**ことになる（下記）。この規模には重装備 |
| C-3 | 暗号化してリポジトリに入れる（git-crypt 等） | ⚠️ **publicリポジトリで暗号鍵の管理コストが増える。** 過剰 |

**C-1 を採用**。⚠️ **リポジトリには一切置かない**（`.jks`・パスワードとも）。
📌 **バックアップは開発者個人が自分の道具で行う**ので、**プロジェクトでは扱わない。**

⚠️ **パスワードの受け渡しは `App/.env`（gitignore済）経由**とし、
config plugin がそれを読んで `android/` に書く。

### D. Playへのアップロードを自動化するか

⚠️ **どの案を選んでも初回は手動が必須。**
**Play Developer API は「すでに存在するアプリ」しか更新できない**ため、
**パッケージ名がPlay Consoleに登録されるまで、自動化を作っても使えない。**

| | 案 | 評価 |
|---|---|---|
| **D-1** | **まず手動で運用し、後で判断** ✅ | **配る相手は20人以下・更新頻度も低い。** ⚠️ **自動化すると署名鍵をCIに置くことになる** |
| D-2 | fastlane（`supply`） | Android界の標準（42,000スター・organization運営）。⚠️ 学習コストは高い |
| D-3 | `r0adkll/upload-google-play` | 手早い。⚠️ **個人リポジトリでビルド済みバンドルを実行する**ため、**コミットSHA固定が前提** |

**D-1 を採用**（保留ではなく、**当面は手動で運用すると決めた**）。
⚠️ **どのみち初回は手動なので、後から入れても損をしない。**

⚠️ **自動化する場合も AWS の CodeBuild には入れない。**
📌 **`buildspec.yml` は「`App/` は Expo で出すのでここには無い」方針**であり、
**Androidのビルド環境をCodeBuildに用意するのは割に合わない。**
📌 **アプリ側をAWSに依存させない**方針とも整合する（バックエンドとは別物として扱う）。

## 決定

| # | 決定 |
|---|---|
| **A** | **`versionCode` は `app.json` の `version` から config plugin で自動導出する** |
| **B** | **既定は `arm64-v8a` のまま。配信用ビルドのみ環境変数で全ABIに切り替える** |
| **C** | **upload key の原本は `~/.keystore/`（リポジトリ外）に置く。パスワードは `App/.env` 経由。Play App Signing を使う** |
| **D** | **当面は手動でアップロードする。自動化するなら GitHub Actions（AWSには入れない）** |

⚠️ **本番公開はしない。** 内部テストに留める
（本番公開には**12人を14日間集めるクローズドテスト**が必要になり、
**Data safetyフォームも必須**になる。⚠️ **本アプリは音声と位置情報を扱う**）。

## 影響

- **`App/plugins/` に config plugin が2つ増える**（`versionCode`・署名設定）。
  ⚠️ **`withSingleAbi.js` は環境変数を見るように変わる。**
- ⚠️ **`App/.env` が新たに必要になる**（署名鍵のパスとパスワード）。
  **gitignore 済みだが、無いと release ビルドができない**ので `App/SETUP.md` に手順を書く。
- **リリースの成果物が APK から AAB に変わる**（`assembleRelease` → `bundleRelease`）。
  📌 **手元での動作確認には引き続き APK を使う**（AABは直接インストールできない）。
- ⚠️ **`version` を上げる意味が増えた。** これまでは「実機で更新を判別するため」だったが、
  **今後は `versionCode` の源にもなる**ので、**上げ忘れるとPlayが受け付けない。**
- ⚠️ **Play Console の登録（$25・身分証）が前提になる。** 確認に最大数日かかる。
- 📌 **配る相手には手順書が要る**（既定アシスタントの解除・APIキーの入力・戻り先アプリの選択）。
  ⚠️ **アプリが入っただけでは使えない。**
