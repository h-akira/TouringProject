# 008. ドキュメントをユニットごとに分け、learning・research を submodule にする

- **日付**: 2026-09-26（最終更新 2026-09-27）
- **ステータス**: 採用

## 背景

リポジトリを分けた（[007](007_repository_split.md)）後も、設計・経緯・調査・学習の文書は親に集まっていた。

- 親の `docs/` の大半が単一のユニット（App・Backend）に固有で、Agent の設計文書は無かった。
- ADR の半分が App に固有で、改訂の節が重なり、最終的な決定が一読で分からなかった。
- 調査（`pre-research/`）には、実装前の検討・実装後のデバッグ記録・判断が混ざっていた。
- `AGENTS.md`・`README.md`・`.memory/` が肥大し、ユニット固有の規則と共通の規則が同居していた。

## 選択肢

### 文書の置き場

| 案 | 判断 |
|---|---|
| A. 親に集約したまま整理だけする | 却下。ユニットを単体で開いたときに設計が見えない |
| **B. ユニット固有の docs・adr・AGENTS.md は各ユニットに、共通のもの（要件・技術方針・ユニットの定義・契約）だけ親に置く** | 採用 |

### ユニットに親の docs をどう届けるか

| 案 | 判断 |
|---|---|
| C. OpenAPI だけを App に写す | 却下。命名規約・リージョン・SSM・呼び出し形式など、他の契約も各ユニットが要る |
| **D. 親の `docs/` を丸ごと各ユニットの `docs-parent/` に写す**（`docs/sync.sh`。手動） | 採用。ユニットは単体でクローンしても契約を読める |
| E. 親の `adr/` も写す | 却下。経緯はユニットの実装に要らない。docs で分からなければ親の adr を見に行けばよい |

### ADR の番号と中身

| 案 | 判断 |
|---|---|
| F. 元の番号を維持する（欠番が残る） | 却下。番号から時系列が読めなくなる |
| **G. リポジトリごとに 001 から振り直す**（日付順） | 採用。旧番号との対応は [README.md](README.md) に一度だけ置く |
| H. 改訂の節を足し続ける | 却下。最終的な決定が一読で分からない。ADR は経緯を書くものなので、覆った内容は却下案と理由として本文に入れれば足り、元の文は git の履歴に残る |
| **I. 決定が覆ったら本文を書き直す**（却下案と理由は残す） | 採用 |

### learning と research

| 案 | 判断 |
|---|---|
| **J. 別リポジトリにし、submodule で束ねる**（learning は public、research は private。履歴は引き継がない） | 採用。learning はプロジェクト横断の学習教材として独立させる。research はバグ調査も入るので `pre-research` から改名し、非公開にする |
| K. 親に残す | 却下。親の履歴と文書の量がこれらに引っ張られる |

### リンクの規則

- learning へのリンクはどこからも張らない（名前を挙げるのは可）。learning から外へは例示として絶対 URL で張ってよい。
- research へは、参考としてどこからでも絶対 URL で張ってよい（非公開なので他の人には切れて見える）。research は独立が原則なので数は少なく保つ。
- 親の `docs/` は起点なので、`docs/` の外へはリンクしない（research への参考を除く）。写しの中で相対リンクが別の文書を指す事故も、これで起きない。

## 決定

案B・D・G・I・J と、上のリンクの規則を採る。規則の本体は親の `AGENTS.md` に置く。

## 影響

- ⚠️ 親の `docs/` を変えたら `docs/sync.sh` を実行し、各ユニットで `docs-parent/` をコミットする（手動。忘れるとユニットは古い契約のまま）。
- ADR の番号が変わったので、古いコミットやメッセージの番号は [README.md](README.md) の対応表で読み替える。
- `CLAUDE.md` は置かず、各リポジトリに `AGENTS.md` を置く。ユニットのファイルを触る前に、そのユニットの `AGENTS.md` を読む。
- README は概要・利用方法・手順だけにし、設計は docs に置く。
