# ハンズフリー起動の方式調査（US-2.04）

> 実施日: 2026-08-16 / 前提: [../../docs/00_user_stories.md](../../docs/00_user_stories.md) US-2.04・補足C

>
> **問い**: スマホに触れずにアプリを起動する手段は、Android + React Native で成立するか。

## ✅ 結論：方式B（アシスタントとして登録）を採用

**自アプリを Android の「既定のアシスタント」にし、インカムのボタンで起動する。**
⚠️ **代償として Google Assistant を明け渡す。**

| 方式 | 判定 | 決め手 |
|---|---|---|
| A. メディアボタン | ❌ 却下 | **押しやすいボタンはメディアキーを送らない**。使えるのは音楽操作用だけで、**他アプリに奪われる** |
| **B. アシスタント登録** | ✅ **採用** | **ボタンが起動するのは「既定のアシスタント」。** ⚠️ **実機で確認済み** |
| C. ウェイクワード | ❌ 却下 | ⚠️ **常時マイクを占有する。** 加えて**インカムのマイクで拾えるかも未知** |

**⚠️ 受け入れる代償:**

- ❌ **Google マップの音声入力を失う**（回避策なし）
- ❌ **Google Assistant を既定から外す**（端末に1つしか置けない）
- 📌 **音声案内は残る**ので、**ナビとして目的地まで走ることは問題ない**
- 📌 **設定を戻せば復帰できる**（不可逆ではない）

> 📌 **決め手は「確実に動くこと」。** 方式Cは**成立するかどうか自体が未知**なうえ、
> **常時マイク占有の代償は確定していた。**

## 次の一手：実装（US-2.04）

📌 **実機で確かめるべきことは終わっている**（[FINDINGS.md](FINDINGS.md)）。
⚠️ **残る論点は実装しないと分からない。**

1. **Expo Development Build への移行**（⚠️ **ここで初めて Android SDK に踏み込む**。
   `learning/` に残す価値がある）
2. `VoiceInteractionService` + `VoiceInteractionSessionService` を **Kotlin で書く**
3. `res/xml` の `<voice-interaction-service>` メタデータと `BIND_VOICE_INTERACTION` 権限
4. **既定のアシスタントに手動で設定**（⚠️ **再インストールのたびに外れる可能性**）
5. **セッションから既存の録音・送信処理を呼ぶ**
   （📌 **アプリ本体の処理は既にあるので、起動経路をつなぐだけにする**）

> ⚠️ **実機は停車状態で先に確かめる。** ⚠️ **`App/app.json` の `version` を上げる。**
