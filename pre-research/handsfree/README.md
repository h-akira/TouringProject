# ハンズフリー起動の方式調査（US-2.04）

> 調査: 2026-08-16 / 実装・実機確認: 2026-08-17
> 前提: [../../docs/00_user_stories.md](../../docs/00_user_stories.md) US-2.04・補足C
> （走行中の画面操作は法律上できない＝「アプリを開いて押す」は解にならない）

## ✅ 結論：`VOICE_COMMAND` の intent-filter で実装。実機で起動を確認済み

**インカムのボタンを押すと、本アプリが自動で前面に出て録音が始まるところまで実機で成立した。**
⚠️ **代償として Google Assistant を明け渡す**（変わらず有効）。

📌 **調査時点の想定（`VoiceInteractionService` で既定アシスタントになる）は、
実装時に実機で成立しないと判明し、`VOICE_COMMAND` 方式に変更した。**
詳しい経緯は [adr/006](../../adr/006_handsfree_launch_mechanism.md)。

| 方式 | 判定 | 決め手 |
|---|---|---|
| A. メディアボタン | ❌ 却下 | 押しやすいボタンはメディアキーを送らない |
| B. アシスタント登録（`VoiceInteractionService`） | ❌ **実機で不成立と判明** | インカムのボタンはこの経路を通らない（[adr/006](../../adr/006_handsfree_launch_mechanism.md)） |
| **`VOICE_COMMAND` intent-filter** | ✅ **採用・実機確認済み** | インカムのボタンが実際に送るのはこのIntent |
| C. ウェイクワード | ❌ 却下 | 常時マイクを占有する |

**⚠️ 受け入れる代償:**

- ❌ **Google マップの音声入力を失う**（回避策なし）
- ❌ **Google Assistant を既定から外す**（端末に1つしか置けない）
- ⚠️ **マップアプリの上に本アプリが被さる**（新規タスクで前面に出るため）
- 📌 **音声案内は残る**ので、**ナビとして目的地まで走ることは問題ない**
- 📌 **設定を戻せば復帰できる**（不可逆ではない）

## 次の一手：録音終了のハンズフリー化

**起動はハンズフリー化できたが、話し終えたら画面のボタンを押す必要がある。**
30秒の自動送信タイムアウトはあるが、待つには長い。

無音検知（VAD）が有力候補。詳細は [.memory/issues.md](../../.memory/issues.md)。
