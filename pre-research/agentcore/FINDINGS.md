# AgentCore 検証結果（実測ログ）

> 実施日: 2026-07-29 / リージョン: ap-northeast-1 / モデル: `jp.anthropic.claude-sonnet-4-6`
> **問い**: 同じ `runtimeSessionId` を渡せば、会話は本当に継続するのか。
> 手順は [SETUP.md](SETUP.md)、設計判断は [README.md](README.md)。

## 結論

| 検証項目 | 結果 |
|---|---|
| 同一セッションIDで文脈が継続するか | ✅ **する**（ローカル・デプロイ済みの両方） |
| 別セッションIDで文脈が漏れないか | ✅ **漏れない**（対照実験で確認） |
| 3ターン以上遡れるか | ✅ **遡れる**（2ターン前を正しく参照） |
| 履歴の永続性 | ❌ **プロセス内メモリのみ**。タイムアウト・再起動で消える |

## 1. 検証設計：なぜ「指示語」で試すのか

**指示語（「それ」）だけを含む質問**を投げる。前のターンを覚えていなければ答えようがないので、
正しく答えられれば文脈保持の証拠になる。

ただしこれだけでは不十分。モデルが**たまたま推測で当てた**可能性を排除できない。
そこで**対照実験**として、同じ質問を**新しいセッションID**でも投げる。

```
[A] 同じID    : Q1「富士山の標高は？」→ Q2「それは何県？」  → 答えられるはず
[B] 新しいID  :                        Q2「それは何県？」  → 答えられないはず
```

**Bが正しく失敗すること**が、Aの成功を意味あるものにする。

## 2. ローカル実行での結果

スクリプト: [`try_session.sh`](try_session.sh)

### 2.1 対照実験

```
[A] same session id (continuity-1785333547-a)
Q1: 富士山の標高は？
A1: 富士山の標高は3776メートルです。日本で一番高い山ですね。

Q2: それは何県にありますか？
A2: 富士山は静岡県と山梨県の2県にまたがっています。山頂部分は主に山梨県側になります。

[B] fresh session id — control (continuity-1785333551-b)
Q2 only: それは何県にありますか？
A: 直前の会話履歴がないため、「それ」が何を指しているか判断できません。
   もう少し詳しく教えていただけますか？
```

**Bが期待通り失敗している。** セッション単位で文脈が分離されている。

### 2.2 3ターンの遡及

```
Q1: 静岡県の名物を1つ教えて
A1: 静岡おでんが有名です。黒はんぺんや牛すじなどの具材を、黒い出汁で煮込んだ
    静岡独自のおでんで、駄菓子屋さんでも気軽に食べられます。

Q2: それはいくらくらい？
A2: 1串あたり100円前後が相場で、お店によっては50円くらいから楽しめるところもあります。
                                        ↑ 1ターン前（静岡おでん）を参照

Q3: 最初に聞いたのは何県だった？
A3: 静岡県です。
    ↑ 2ターン前まで遡って正答
```

直前だけでなく**会話全体**が保持されている。

### 2.3 ログ：セッションごとの独立性

`turns_before` は1往復ごとに2増える（user + assistant の2メッセージ）。

```
NEW creating agent for session: continuity-...-a
    session=continuity-...-a turns_before=0
    session=continuity-...-a turns_before=2     ← 履歴が積み上がる
NEW creating agent for session: continuity-...-b
    session=continuity-...-b turns_before=0     ← 対照群は常に0
NEW creating agent for session: multi-...
    session=multi-... turns_before=0
    session=multi-... turns_before=2
    session=multi-... turns_before=4            ← 3ターン分
```

セッションIDごとに独立し、**混線していない**。

A2: 先ほどお伝えしたとおり、静岡県と山梨県の2県にまたがっています。
    ^^^^^^^^^^^^^^^^^^^^^^ ← 前ターンを認識している決定的な表現

[B] fresh session id — control (deployed-continuity-b-1785335800-padding)

**「先ほどお伝えしたとおり」** は、モデルが前のターンを明示的に参照している証拠。
ローカルと**同じ挙動**が確認できた。

## 4. ⚠️ 重大な制約：履歴はプロセス内メモリ

CLIが生成するコードのコメントにも明記されている:

> Reuses one Agent per session_id so each session keeps its own **in-process**
> conversation history (**best-effort; resets on cold start**).
> For durable history, attach a session manager.

| | 挙動 |
|---|---|
| microVMが生きている間 | ✅ 履歴が保持される |
| **アイドルタイムアウト（既定15分）後** | ❌ **消える** |
| **コールドスタート後** | ❌ **消える** |
| 消えた後に同じIDで呼ぶと | ⚠️ **エラーにならず、新しい会話として始まる** |

**最後の行が実務上いちばん危険。** 「30分前の続きを話す」つもりが、
黙って別の会話になっていても気づけない。

### この制約は本プロジェクトでは問題にならない

**要件は「一問一答＋α」であり、連続して聞くときに文脈が繋がればよい。**
15分以上あけて前の会話の続きを求める使い方は想定しない。

| 要件 | 現状で足りるか |
|---|---|
| 連続した質問の間で文脈が繋がる | ✅ **足りる**（実測済み。§2〜§3） |
| 15分以上あけて続きを話す | 要件外 |

→ **セッションを越えた記憶（AgentCore Memory）は採用しない。**
　「セッション断後の実挙動」の検証も**不要**と判断（要件を満たすかどうかに影響しないため）。

> 将来「走行ログを残す」「訪問地を記録する」といった話が出たら、それは**会話の記憶ではなくDB連携**の課題。
> AgentCore Memory（会話から要点を自動抽出する仕組み）とは別物として設計する。

## 5. 検証中に判明した実務上の注意点

| 事象 | 内容 |
|---|---|
| **セッションIDは33文字以上** | 短いと `ValidationException`。UUIDだけだと足りない場合がある |
| **`/ping` であって `/health` ではない** | 本アプリのAPIが持つ `GET /health` とは別レイヤーの別物 |
| **`agentcore dev` は対話型TUI** | バックグラウンド実行不可。Python直接起動で回避 |
| **CLIタイムアウト ≠ デプロイ失敗** | CloudFormation側は進行し続ける。`wait` で確認する |
| **`agentcore invoke` が使えなくなる** | deploy中断で `.cli/deployed-state.json` が未更新になるため。boto3で直接呼べる |
